# M13 · 技术交流留痕规则

> 归属：创新之门 — 第 5 关 · 分钱定规矩
> 关内作用：对外谈技术怎么留底、怎么防泄密、怎么防权属扯皮
> 用法：由总入口 SKILL.md 路由到本模块后，按 E 段步骤执行，按各模块「交付物与完成标准」出件。

---

## R — 原文 (Reading)

> "我们做什么事情我们都要留底子，都留记录，大家都有一个证据，说得清，道得明，谁是谁的就是谁的。……涉密东西我不看、不听、不说、不传，我不知道就不存在泄密。"
>
> — 本书作者，《与网友交流创新发明的几个问题说明.md》

---

## I — 方法论骨架 (Interpretation)

和外部人员（网友、民间发明家、潜在合作方）做技术交流，既要开放又要防纠纷，作者定了一套规则：

1. **用录音代替即时文字/电话**：不打短信式零碎文字、不随叫随到打电话；提问方先打腹稿列提纲，把要说的事有条理地录成录音发给对方，对方用闲暇时间反复回放。录音同时是工作记录、历史资料，也是"发明创新的证据"。
2. **问题描述五段结构**（★校注：原文以"第一……第五部分"列举，"五段式"为整理者概括词）：①现状——你做的这个领域目前大家都在怎么做；②不足——现有技术方案/产品/工具有什么问题；③目标——你想做什么创新、达到什么目的；④方法——你想到的办法是什么；⑤问题清单——你遇到的、想请对方解决或判断的问题，逐条列出（数量不限）。描述不清的，不进入讨论。
3. **保密责任自负**：想保密的内容就不要拿出来说（"你就不要告诉我"）；涉密内容"不看、不听、不说、不传"，不知道就不存在泄密；需要保密的内容要么换个不录音的场合明确告知，要么自己负责脱密。
4. **留底双向保护**：双方各自留存交流记录，"你有底子我也有底子"，日后若发生权属纠纷有据可查、说得清道得明——既保护提问方的技术，也保护解答方的名誉。

## A1 — 应用示例 (Application Example)

### 示例 1: 网友发明咨询的留痕处理演练
- **类型与来源**: 原书未提供独立案例（《与网友交流创新发明的几个问题说明.md》全篇即作者为交流对象预录的规则说明，属规则陈述而非案例），以下为按原书规则的**合成演练**，仅用于复算规则，不代表作者经历或现实结果。
- **问题/输入**: 一位民间发明人想请技术专家看自己"改进锅炉"的想法，但只发来一句"我有个很牛的发明，电话里细说"。
- **方法论的使用**: 按规则处理——①不约即时电话，请对方按五段结构录一段语音：目前锅炉节能大家都在怎么做（现状）、现有方案有什么问题（不足）、他想改成什么样（目标）、他打算用什么办法（方法）、他卡在哪几个具体问题上（问题清单）；②告知对方：需要保密的部分请自行剔除后再录，录音默认双方留底；③收到录音后同样在留痕前提下回复（录音 + 草图）。
- **结论**: 交流效率提高（可反复回放、错峰进行），且从第一轮沟通起双方权属边界清晰，杜绝"谁偷了谁的创意"式纠纷。
- **结果**: 合成演练，无现实结果；可复算的规则点是"五段齐才讨论 + 双方留底 + 涉密不谈"三条。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个模块？

1. 用户是技术方/专家，经常有人来找他"帮忙看看发明/方案"，沟通零散低效、还有被反咬"剽窃"的顾虑。
2. 用户要向专家/合作方请教技术问题，想问得专业、一次问清，提高被认真对待的概率。
3. 合作洽谈涉及技术细节披露，用户纠结"说多少合适、怎么防对方拿了方案绕开我"。
4. 交流结束后担心日后知识产权权属扯皮，想建立"有据可查"的沟通习惯。
5. 对方神神秘秘不肯说细节又要求帮忙，用户不知道怎么回应。

### 语言信号 (用户的话里出现这些就应激活)

- "技术交流怎么防泄密 / how to protect IP in tech discussions"
- "有人找我聊发明，要不要录音 / 留证据 / keep a record"
- "怎么向专家描述我的技术问题 / 问问题要说什么"
- "对方不肯说细节还要我帮忙"
- "怕以后扯皮 / 创意被偷 / idea theft / 权属纠纷"

### 与相邻模块的区别 

- 与 M08 技术方-企业合作落地流程（技术方-企业合作落地流程）的区别：合作流程卡管商务推进的顺序与谈判红线；本模块管一切对外技术交流中的**沟通纪律与证据留存**，是跨场景的规则，在合作流程的交流/调研环节中同样适用。
- 与 M09 企业节能创新点调研七步法（企业节能创新点调研七步法）的区别：调研七步法中的"与一线工程师交流"是现场技术作业；本模块是交流本身的留痕与保密规则，两者互补——调研时按本模块录音留底、涉密回避。
- 与真假需求/项目筛选类 模块 的区别：那些卡判断"这个项目/需求靠不靠谱"；本模块不判断内容价值，只管"怎么谈、怎么留证"。

## E — 可执行步骤 (Execution)

**必需输入**:
- 交流场景（谁找谁、交流目的是请教/合作/咨询）；
- 对方发来的问题描述或沟通请求；
- 双方对保密事项的声明（哪些内容不进入交流）。
- 缺"对方问题描述"时不能开始实质讨论——五段描述是本规则的入场券，不能静默跳过。

**交付物与完成标准**: 输出一份《交流留痕记录》：①对方五段描述的整理版（现状/不足/目标/方法/问题清单，标注各自"已提供/缺失"）；②本次交流的录音或文字留底说明（时间、参与人、介质）；③保密边界记录（哪些内容双方确认不谈）；④回复要点。完成标准：五段中缺失的段落被显式标出并要求对方补充，不留"印象式"模糊描述。

被路由到本模块后，按以下步骤执行：

1. **立规则（交流前）**
   - 向对方申明三条：①请用录音/结构化文字代替零散即时消息，先列提纲再表达；②双方交流内容默认各自留底，作为权属证据；③想保密的内容请不要讲，涉密内容不看、不听、不说、不传。
   - 完成标准：对方确认接受规则；对方拒绝留底或坚持"你发誓保密我才说"→ 建议用户明确谢绝本次交流（作者规则：不承担保密责任，帮不了就不帮）。

2. **五段描述审查（判停闸门）**
   - 检查对方问题描述是否覆盖五段：现状 → 不足 → 目标 → 方法 → 问题清单。
   - 完成标准：五段齐全，且问题清单是逐条的具体问题（不是"您给看看行不行"）。
   - 判停条件：任一段缺失或空泛 → 不进入技术讨论，把五段模板发给对方请其补充后再谈。

3. **留痕回复与归档**
   - 以可留存的形式（录音 + 草图，或结构化文字）回复，内容同样留底；交流结束归档：时间、参与人、讨论要点、双方权属确认。
   - 完成标准：归档记录可供日后独立还原"谁说了什么、谁贡献了什么"。

## B — 边界 (Boundary) ★

### 不要在以下情况使用本模块

- 正式商业秘密保护场景（需要 NDA 法律效力的尽调、技术许可谈判）——本规则是"丑话说在前面"的民间纪律，替代不了保密协议；金额大、风险高的披露必须签正式 NDA。
- 内部团队日常协作——规则针对外部、信任基础薄的交流对象，对内套用会制造对立感。
- 涉及国家秘密或受管制技术——"涉密不谈"是回避策略，不代表交流此类内容合法；受管制信息应走合规渠道。

### 作者在书中警告的失败模式

- **通话不录音、说完就白说**（规则篇）："上次说到哪儿是随口胡说，这样很不负责任"——无留痕的交流既低效又埋纠纷隐患。
- **想说又不说、要求对方担保密责任**（规则篇）："你要是想让我帮你，你又不想告诉我细节，那你就不要联系我"——描述不清的求助无法进行，保密责任作者明确不承担。
- **发明权属无据可查**：不留底子的交流日后"偷专利、偷创意"各说各话；留底子之后"我也保护我的名誉，你也保护你的技术"。

### 作者的盲点 / 时代局限

- 具体工具建议已过时（BOOK_OVERVIEW 第 3 节）："QQ 远胜微信""下载录音 APP"等应抽象为"异步、可留存、可回放的沟通介质"原则，按当下工具执行。
- "录音即证据"的法律效力被作者高估：单方录音在诉讼中的证据能力受合法性、完整性限制，重要权属确认仍应补书面文件（邮件确认、协议）。
- 作者对民间发明家态度在语料中前后不一（"妄想家" vs "可收编的合作者"，glossary 勘误 7）；本模块采用其扶助口吻一篇的规则，实际使用中对来访者的筛选仍应回到"有无基础知识 + 是否结合市场"判据。

### 容易混淆的邻近方法论

- 与正式保密协议（NDA）混淆：本模块是交流纪律不是法律文书；NDA 管"说了之后的法律责任"，本模块管"说不说、怎么说、怎么留证"。
- 与专利查新/交底书撰写混淆：五段描述是口头交流的结构，不是专利申请文件；申请专利的披露要求另由专业代理处理。
- "五段式"命名注意：此词为整理者概括（glossary 勘误 13），原文只有"第一……第五部分"的列举；引用原文时不得称"五段式"为原文用词。
