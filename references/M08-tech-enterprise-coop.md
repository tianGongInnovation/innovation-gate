> 归属：创新之门 — 第 4 关 · 进企业

## I — 方法论骨架 (Interpretation)

技术方（创新服务方）要和企业做成节能减排/技改类合作，不是先谈方案，而是先过一道"准入闸门"：三个前提必须同时成立——能对接到实际控制人（一把手）、资金有着落（自筹或 EMC 合同能源管理）、企业有说干就干的执行力团队。任何一条不满足，宁可不谈，因为缺一条合作就会空转或烂尾。

过了闸门之后按固定步骤推进：企业先派人来技术方所在地初谈（验双方的诚意与实力）→ 邀请技术方赴企业现场考察，并直接对接一线技术人员而非只听领导转述 → 技术方在一两天内给出若干建议方案（各含投入、产出、风险、可行性）→ 做什么、先做什么完全由企业拍板，技术方和中间人都不强行推荐 → 企业定方向后双方起草合作协议（明确技术服务费、责权利、知识产权归属、终止后果）。流程中有一条费用红线：技术方上门调研的差旅接待费必须由企业或中间人承担，连这点费用都不愿出的企业视为无诚意，不去。此外项目本身还要过规模门槛（跨地投入的项目应在几十万级以上）和短平快纪律（半年一年见效）。

## A1 — 应用示例 (Application Example)

### 示例 1: 天津江天重工蒸汽机车改造（完整商业闭环）
- **类型与来源**: 实务案例，《创新推进委交流.md》
- **问题/输入**: 江天重工的燃煤蒸汽机车被环保部门逼停，企业有真实的停产压力（真需求 + 有动力）。
- **方法论的使用**: 厂长主动在网上找到技术方（满足"企业有内在动力"）；双方签合同，一周内完成液态 CO₂ 改造，费用十几万元（短平快：投资小、周期极短）。
- **结论**: 真实需求（环保合规）+ 成熟技术（蒸汽机平台 + 液态 CO₂）+ 具体行动（快速改造）三要素闭环，项目落地。
- **结果**: 改造后零排放，持续日常运营近一年（书中记录，无第三方审计）。

### 示例 2: 钢铁厂现场调研一次给出 8 个节能方向
- **类型与来源**: 实务案例，《创新推进委交流.md》
- **问题/输入**: 技术方受邀到钢铁厂现场考察。
- **方法论的使用**: 按流程中"现场调研 + 与一线技术人员直接沟通"环节执行，用能量流框架当场识别出 8 个节能改造方向，供企业选择（企业拍板原则：由企业决定先做什么）。
- **结论**: 现场调研是方案产出的直接来源，一两天内即可形成建议方向。
- **结果**: 原书未交代企业是否采纳及实施结果，结果未说明。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个模块？

1. 用户手里有节能/减排/技改类技术或方案，一家企业表达了合作意向，用户不知道第一步该干什么、按什么顺序推进。
2. 用户（技术方或中间人）在犹豫要不要花差旅费去某企业调研，或纠结"对方一直说感兴趣却不推进"还要不要继续跟。
3. 用户要去企业谈合作，想提前知道谈判中哪些条件必须坚持（差旅费、见一把手）、哪些决定权必须让给对方。
4. 用户是中间人，想撮合技术方与企业合作，问"怎么开始、我该怎么牵线"。
5. 用户给企业出了方案，企业问"你的意见是先做哪个"，用户纠结该不该替企业做选择。

### 语言信号 (用户的话里出现这些就应激活)

- "企业想跟我们合作，怎么开始 / how to start the cooperation"
- "要不要去他们厂里调研 / 差旅费谁出 / who pays the travel cost"
- "对方一直说感兴趣但没下文 / they keep saying interested but never act"
- "见不到老板，只和中层谈 / only talking to middle managers"
- "方案给了，先做什么让我定 / 要不要替企业拍板"

### 与相邻模块的区别 

- 与 M10 成果转化获利与退出结构（成果转化获利与退出结构）的区别：本模块管"怎么把合作谈成并落地"的流程与纪律；获利结构卡管"谈成之后钱和股权怎么分、怎么退出"。同一合作链条上的不同环节——先按本模块推进流程，流程走到起草协议阶段时调用获利结构卡设计分配。
- 与 M09 企业节能创新点调研七步法（企业节能创新点调研七步法）的区别：调研七步法是本流程"现场调研"这一步内部的技术作业方法；本模块是整个商务合作流程的骨架。到企业现场后具体怎么找节能点，调用调研七步法。
- 与 M11 合作协议条款审查清单（合作协议条款审查清单）的区别：本模块推进到"起草协议"环节时，条款该查什么用清单卡核对；本模块不展开条款细节。

## E — 可执行步骤 (Execution)

**必需输入**:
- 合作对象基本情况（企业类型、规模、所在行业、能耗/排放痛点）；
- 对接渠道（直接对接 / 中间人介绍，中间人是谁、影响力如何）；
- 拟合作项目的初步方向（节能减排/技改领域）。
- 缺失"对接渠道是否触达实际控制人"这一信息时必须先询问，不能默认"对方是负责人"就算数。

**交付物与完成标准**: 输出一份《合作推进状态单》，含：①三前提逐项核验结论（通过/不通过+依据）；②当前所处流程步骤与下一步动作；③红线检查结果（差旅费、规模门槛、短平快）。完成标准：三项前提各有明确证据或明确判停结论，不允许写"基本可以""应该没问题"。

被路由到本模块后，按以下步骤执行：

1. **三前提核验**
   - 逐项检查：①能否见到或影响实际控制人（中层对接不算）；②资金是否有出处（企业自筹 / 中间人筹资 / EMC 模式客户能接受）；③对方是否有执行力信号（说看就看、说开会就开会，或明确说"不做"也算有执行力；态度暧昧不算）。
   - 完成标准：每项前提有具体事实支撑（见过谁、钱从哪来、对方近期什么行动），三项全过进入步骤 2。
   - 判停条件：任何一项不满足 → 停止推进，输出"暂不合作"结论及缺失项；告知用户可保持联系待条件成熟，不建议"先处处看"。

2. **推进流程步骤**
   - 定位当前阶段并按序推进：a) 邀请企业派人（技术/生产负责人即可）来技术方初谈——对方连一个人都派不来即亮红灯；b) 受邀赴企业现场考察，直接与其环保/节能技术人员沟通，不听二手转述；c) 一两天内产出若干建议方案，每个方案写明投入、产出、风险、可行性。
   - 完成标准：方案清单交付企业，每份方案四要素齐全。
   - 判停条件：赴企业前必须先确认差旅接待费由企业或中间人承担——不承担则不去，返回步骤 1 重新评估对方诚意。
   - 红线检查（本步骤内嵌）：项目规模是否达几十万级以上、能否半年至一年内见效，不满足则建议降级为"帮忙"性质而非正式合作。

3. **企业拍板 + 起草协议**
   - 把"做什么、先做什么"的决定权完整交还企业方，技术方和中间人只提供方案不强行推荐；企业选定方向后，配合起草合作协议，协议须含技术服务费、双方责权利、知识产权归属、终止条款。
   - 完成标准：企业方明确选定合作方向与项目（有书面或会议纪要级证据），协议要点齐备进入条款审查（调用 M11 合作协议条款审查清单）。
   - 判停条件：企业长期不拍板 → 回到步骤 1 执行力项复核，考虑判停。

## B — 边界 (Boundary) ★

### 不要在以下情况使用本模块

- 面向 C 端消费者销售产品/服务——本流程是 B2B 技术合作 SOP，不适用于零售获客。
- 企业内部自己的技改立项（无外部技术方）——三前提中的"中间人/技术方"角色不存在，套用会扭曲。
- 政府课题申报、科研经费类合作——作者明确"这种事别找我"（ce14：以经费为导向而非市场为导向的项目不在此流程内）。
- 信息化/软件类项目——作者在能力圈上明确排除（ce19），不要拿本流程去论证大数据、AI 类合作。

### 作者在书中警告的失败模式

- **只和中层打交道必败**（ce17）："见不到的（实际控制人），项目最后我们的经验都没戏。"中层无权拍板、不知企业资金与战略实情，谈得再热闹也无法成交。
- **合作方无执行力，"好好好"然后没有下文**（ce16）：夸完项目一两个月不谈第二回合、决策时不停追问"有没有人做过"，这类对象让项目在"下次再谈"中烂尾。
- **上杆子不是买卖**（ce13）：对无内在需求、无资金、无执行力的企业强行推销，对方能"找出一百个理由"，时间精力全部白费。

### 作者的盲点 / 时代局限

- 书中关于政府合作、EMC 补贴、职称评价等论断基于 2013–2018 年经验，政策环境已变化，引用时需做时代校注。
- 书中的动员话术（"风险小、一干就成""一生只失手一次"类自我叙事）应剥离，不要作为成功率承诺输出给用户；"三前提通过"不代表项目必然成功。
- 流程中"一两天出方案"依赖作者个人技术储备，用户直接照搬时应根据自身能力调整时限预期。

### 容易混淆的邻近方法论

- 与"科技成果转化"常规打法混淆：作者明确反对"拿着技术找市场"（ce08），本流程是以企业需求为起点的合作流程，不是给已有专利找买家的推销流程。
- 与节能服务公司（ESCO）行业通行的 EMC 全流程混淆：本流程只把 EMC 当作"资金落实"的选项之一，不是节能服务产业的完整商业模式。
